# tutorial/ — what is published here

This directory holds the design and deployment documentation that the code
and its tests actually depend on. It is deliberately small.

| Path | What it is | Why it is here |
|---|---|---|
| `v2-entry/` | the isolated entry's example configuration and its design notes | `tutorial/v2-entry/isolated.example.toml` is read **by the test suite** (`v2/internal/isolated/assembly_test.go`, `hybrid/entry_test.go`, `hybrid/support_test.go`, `hybrid/cmd/gopherlearn-integrated/main_test.go`) and `deployment-agent-selectors.toml` is read by the same suite. Without these files the tests cannot run. |
| `v2-production-entry/` | how the production entry is deployed and verified | the configuration template and the compose files point readers at these documents. |
| `v2-j1-knowledge/frozen/image-entry-evidence/` | the sealed Redis image entrypoint evidence | `deploy/redis-stack-preflight.sh` and `compose.integrated.yml` cite these exact files and line numbers as the provenance for the preflight wrapper's behaviour. They are small and keeping them makes the claim checkable. |
| `v2-j1-knowledge/deliverable-hashes.json`, `v2-j1-episode/episode-deliveries.json`, `v2-docker-credential-plan/README.md` | image digest provenance | cited by `tutorial/v2-production-entry/` for the pinned MySQL and Redis Stack digests. |
| `../docs/THIRD-PARTY.md` | dependency license inventory | generated by `../tools/audit-licenses.ps1`. |

## What is not published

Earlier development builds of this project carried their internal experiment
records here: run logs, compressed build and test captures, JSONL datasets and
the design history of the remote-executor (RPC) document pipeline. None of that
belongs in a public release:

- it is internal development material, not product documentation;
- it referenced the private RPC framework, a private document dataset and
  machine-specific absolute paths;
- it was large enough to dominate the repository (about 8,900 files).

The remote-executor pipeline itself is not part of this release at all - see
"当前版本与已知限制" in the top-level `README.md`. Documents are processed by
the backend's own in-process worker pool.
